# Notion access notes (verified)

- Writing a page body: use the markdown write path (`ntn pages edit <page id> < file`). Do NOT pass `{color="yellow_bg"}` / `{color="blue_bg"}` into the Notion MCP create/update tools: they escape the braces and the headings are saved as literal `#{color=...}` text (this happened on five task rows). If you must write through MCP, use the tag form `<h1 color="yellow_bg">…</h1>` / `<h2 color="blue_bg">…</h2>` instead.
- `ntn` is on PATH in the terminal tool but NOT in execute_code. Run Notion API scripts as a .py file through the terminal tool.
- Read a page as markdown: `ntn api v1/pages/<id>/markdown` (JSON with a markdown field; format differs from notion_fetch: headings as `# H {color="yellow_bg"}`, callouts kept as <callout>). Edit with the same format: `ntn api v1/pages/<id>/markdown -X PATCH --data '{"type":"update_content","update_content":{"content_updates":[{"old_str":...,"new_str":...}]}}'`. old_str must match the markdown that GET returned, and must be unique (a 400 'Multiple matches' means include more context, e.g. the neighbouring database tag). Whole-page rewrite: `{"type":"replace_content","replace_content":{"new_str":...}}`.
- Create a page with a markdown body: `ntn api v1/pages -X POST` with parent.data_source_id (タスク ${task_ds}, エピック ${epic_ds}, レビュー ${review_ds}), properties (title as `{"title":[{"text":{"content":...}}]}`) and a top-level `markdown` field. Use the `# H {color=...}` heading form there; `<h1>` tags are saved literally. Code fences with `mermaid` become mermaid code blocks.
- Replacing a span that contains an inline database (e.g. an embedded database in a hub chapter) is refused with 400 (would delete a child database). Never force it; leave the database and tell the user, or ask for confirmation. To move text that spilled under the database, patch with old_str = database tag + the spilled block and new_str = the database tag only.
- Query a data source with pagination: `ntn api v1/data_sources/<id>/query -X POST --data '{"page_size":100,"start_cursor":...}'`. Passing the cursor as a CLI key=value argument fails.
- Create a row: `ntn api v1/pages -X POST --data` with parent.data_source_id, properties in API shape (title, relation [{id}], status {name}, people [{id}]) and children paragraph blocks. Verify the first one, then loop. The relation property of a task to its epic is named エピック.
- Move a page to the trash (recoverable): `ntn api v1/pages/<id> -X PATCH --data '{"in_trash":true}'`.
- Set properties with the Notion MCP notion_update_page update_properties: person = [user id], relation = [page url], select = plain string.
- Add or delete database properties: `ntn api v1/data_sources/<id> -X PATCH --data '{"properties":{"Name":{"select":{"options":[...]}}}}'`; delete with `{"Name":null}`. Changing a property's type in the UI (e.g. url -> relation) wipes the stored values: re-set them afterwards and re-run the reader that depends on the type.
- Create a タスク or エピック row with `python3 ${live}/create_row.py --spec <spec.json>`, not by hand. It applies the DB's default template through `ntn api v1/pages -X POST` with `template: {type: template_id, template_id: <is_default id from GET v1/data_sources/<ds>/templates>}` (measured 2026-11-09 on the タスク and エピック DBs: the body is there within a second; the older note that the template arrives asynchronously, and the old claim that the API cannot apply the default template, do not hold on this path). The レビュー DB is not measured: ask_human.py still builds its body. Database templates themselves cannot be created through the API; ask the user to create them in the UI.
- `PATCH v1/pages/<id>/markdown` update_content with several replacements (measured 2026-11-09): one that matches nothing is dropped SILENTLY (rc 0) when another one matched; only an all-miss call is an error (400 No matches found, ntn exit 5). Check every replacement in the answer, never the exit code. Notion also rewrites the text it stores: `_x_` becomes `*x*`, `<` `>` `|` get a backslash, a bare file name (`create_row.py`) becomes a link: compare text without those marks and write file names in backticks.
- When the user changes a template, align existing pages by diffing the template's markdown against the page and patching chapter by chapter, keeping the page's own content.
- Race with the intake cron: any row created as 未着手 is picked up by the 1-minute intake cron. `create_row.py` avoids it (it creates the row in 進行中 and gives it the spec's status only after the page passed its check); a row made any other way must get 概要 (four rows: 目的 / 完了条件 / 対象外 / 対象) and the checklist immediately after creation, or be created with the final content.
- Page-structure audit after any hand edit of a task page: headings are the template's chapters in order (a task has four: 概要, やることチェックリスト, 作業メモ, 完了レポート), the 完了レポート uses h2 sections, and no text sits under an embedded database. Check by listing headings from the markdown.
- Markdown API PATCH: a new_str that contains a heading line must keep its color suffix (`# 見出し {color="yellow_bg"}`, exactly as GET shows it); writing a bare `# 見出し` silently drops the heading color. Re-check headings with `grep '^#'` on the GET output after every batch.
- MCP update_content cannot match a span that contains a mention (e.g. a template callout with `<mention-page url=.../>`): it returns no_match in every form. Delete such callouts with the markdown API instead (GET shows the callout body with a leading tab and `<mention-page url="..."/>`). Never send a probe op with a guessed shape: a partial match can apply and corrupt the text.
- Bare domains and file names in plain text (example.com/..., controller.py) are auto-linked on save and can swallow the following Japanese text into the link. Write URLs as Markdown links and file names in backticks.
- Database views: `ntn api v1/views?database_id=<db id>` lists views in tab order; `ntn api v1/views/<id>` shows the full config. MCP create_view appends the new view as the last tab; no MCP or public-API way to reorder view tabs was found, so change the first view's settings instead of relying on order.
- Numbered section titles: a heading written as `## 1. 結論` is saved as an EMPTY h2 followed by a numbered-list item `1. 結論`, and a following numbered list then continues the numbering (2., 3., ...). Write section titles without a leading `N.` (or `第1節`/`1）`), then GET the markdown and check that no heading line is empty (`## {color=...}` with no text).
- Notion MCP argument shapes through tool_call: notion_create_pages takes `parent`/`pages` at the argument root (no `data` wrapper), while notion_query_data_sources wraps everything in `data` (`mode: rows`, `data_source_url`, `filter`, `limit`). Its relation filter can return unfiltered rows, so list one epic's tasks with `ntn api v1/data_sources/<id>/query` (filter JSON in a file, output redirected to a file) from a terminal script.
- A template page id is the page URL's 32 hex chars re-hyphenated 8-4-4-4-12; a mis-hyphenated id returns object_not_found, so copy it character by character.
- Bulk reads of many pages (one `ntn api .../markdown` per page) run as a script that can need user approval and time out unattended; do one batched terminal call and do not retry the same script after a timeout.
- Bulk-copying pages between Notion DBs (GET `v1/pages/<id>/markdown`, then POST `v1/pages` with that markdown): run it as a .py file through terminal (execute_code caps a run at 50 tool calls; use xargs -P for plain fetches). Before POST, strip tags the create endpoint rejects with 'Cannot create database reference': `<database ...>...</database>` (use re.S, the tag can wrap a title) and `<unknown .../>` / `<empty-block/>`; `<mention-page>`, `<mention-user>` and tables copy fine. Make the script idempotent (a JSON map source id -> new id, skip done ids), run one page first, then the rest. Verify by re-GETting both sides: body length ratio within 0.9-1.1 and no `<unknown` left. Finish with an index page and say what was deliberately not copied.
- Guard against a retry loop: a failing tool_call repeated 8 times is halted by the gateway. Read the error, change the arguments, and do not resend the same call.
