# Notion の行の作り方・本文の書き方・章立て

SKILL.md の索引から: エピック／タスク／レビューの行を作る・直す、本文を書く、`ntn api` で DB を引く、承認の重複防止を調べるとき。

## 落とし穴（実際に踏んだもの）

- **エピックの行は作成時に DB の既定テンプレートを適用する。** 正しい経路は `scripts/create_row.py` だけ（`python3 ${live}/create_row.py --spec <spec.json>`。手で `POST v1/pages` を組み立てない。中で `template: {"type":"template_id","template_id":…}` を入れ、作成後に読み返して検査する）。`children` で本文を手書きすると、章が見出し2になる・計測ログの4列表が無い・完了レポートの小見出し（実施内容／結果／確認した方法／未確認・残件／次のタスク）が無い、の3点が欠ける。作成後は `GET v1/blocks/<page>/children` で H1 6個・表2個・to_do を数えて確かめる。
- **ブロックの種類（見出しレベル）は PATCH で変えられない**（`validation_error: Block type mismatch`）。直すときは同じ位置に `position: {after_block}` で新しい種類を挿入し、旧ブロックを `DELETE v1/blocks/<id>` で消す。
- **工程の行が同時に「進行中」に見えるのは正常**。連続する工程は1枚のカードにまとまる（MERGE_PHASES）ため。行はゲート制御が作る（未着手で作り、カードを作るときに進行中にする）。
- **承認の重複防止は `${state_dir}/ask_human.json`**。キーは `<エピックID末尾8桁>-承認`（旧形式は `-リリース承認`）、差し戻しのあとは `-r2`。レビュー DB のプロパティは 名前 / ステータス / キー / 対象エピック / 反映済み / 作成日時 だけで、成果物のリンクは行の本文の「根拠」に書く。このファイルは消さない（消すと再投稿する）。
- **`ntn api .../query` に `page_size` を入れると 400**（`query.page_size should be not present`。body でも URL の `?page_size=` でも同じ）。body は filter だけを送り、件数は `has_more` と結果の長さで見る。クエリの JSON はファイルに書いて `-d @<絶対パス>` で渡す（コマンド置換や二重引用符の中の `-d '{"page_size":…}'` は壊れて、エラーにならず 0 件が返る）。0 件の応答を「行が無い」と即断せず、search API でも裏取りする。

## Notion の本文を書く経路（見出しの色）

本文は `ntn pages edit <ページID> < file` のマークダウン経路で書く。Notion MCP の create/update に `{color="yellow_bg"}` を渡すと波かっこがエスケープされ、見出しが `\{color=...\}` の文字列として残る（実際にタスク行5枚で起きた）。MCP で書くなら `<h1 color="yellow_bg">…</h1>` のタグ形式を使う。

- **ブロック API 経路（`POST /v1/pages` の `children`、`PATCH /v1/blocks/<id>/children`）でも色付き見出しは作れる。** その場合は `rich_text[].annotations.color` に **`yellow_background` / `blue_background`** と長い名前で入れる（`yellow_bg` を入れると 400 で、許可される色の一覧が返る）。マークダウン側の `{color="yellow_bg"}`・読み返しの `<span color="yellow_bg">` とは表記が違う。
- 行を新規作成するときは、この経路でプロパティと本文を 1 リクエストにまとめるとタイトル空の事故も減る（プロパティ名・選択肢の正本はリポジトリの `notion/schema.json`。エピックは `名前` / `ステータス` / `種別` / `チャット`）。

## 章立て（タスク・エピック）

- タスクの章立ては（概要 / やることチェックリスト / 作業メモ / 完了レポート。概要の表は4行: 目的 / 完了条件 / 対象外 / 対象（リポジトリとブランチ）。カードIDは作業メモの1行目、担当とエピックは書かない、重複確認は必須手順だが記録欄は無く、見つけた場合だけ完了レポートに書く。完了レポートの h2 は 実施内容 / 結果 / 確認した方法 / 未確認・残件 / 次のタスク）。レビュー依頼（再確認してほしい点）は `hermes kanban request-review` のコメント、成果物のリンクは完了レポートの該当節、人の判断はレビュー DB の行に書く。エピックの本文は（目的 / 候補 / 計測ログ / 管理ログ / 関連ドキュメント / 完了レポート）。打ち手は候補の項目名に含め、状態の正本は工程の行とエピックのステータス属性で、本文には持たない。承認の記録は管理ログに1行（日付・何を承認したか・決定・レビュー行のURL）。
