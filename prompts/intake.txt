Use the skills autonomous-task-execution and product-development-process. Intake job for the Notion task DB 'タスク' (data source ${task_ds}). The execution queue is the kanban board `${board}` (always pass --board ${board}). The only worker profile is `executor`; the independent verifier `reviewer` is started by the dispatcher after kanban_request_review. The pipeline has five phases (要件定義, 設計, 実装, テスト, リリース判定) and one human approval at completion (リリース承認). Phase rows and phase cards are made by the planner and the gate controller, never by this intake.
0. The monitor output lists the pages to take (one line each: page id, URL, tenant). If it is one line starting with `ALERT runaway`, create nothing and respond ONLY with exactly [SILENT] (the guard releases itself once the rows are taken; if it stays stuck, diagnose it yourself by querying the 未着手 rows created in the last 30 minutes and fix duplicates or loops).
1. With the Notion MCP, query pages of the task data source whose ステータス is 未着手. Rows whose タスク名 is exactly a phase name (要件定義, 設計, 実装, テスト, リリース判定) are phase rows: skip them.
2. For each page, check the board (`hermes kanban --board ${board} list --json`, then `show` if needed) for a card that is not done/archived and whose body contains the page URL. Skip pages that already have one.
3. If the work already exists, do not create a card: link the existing work in the page's 作業メモ (no duplicate-check record exists in the 概要) and set the status 完了 only if it is truly the same finished work, otherwise 進行中 with a note that it is merged into the existing item.
4. For each page that is not a duplicate, fetch it (notion_fetch) and create ONE card for the executor. Use the tenant printed on the monitor line of the page (tenant=epic-<last 8 hex of the エピック row id>). A line whose tenant does not start with epic- is an orphan row (no エピック relation; row rules: autonomous-task-execution references/row-lifecycle.md): make NO card for it; raise the epic first (references/epic-creation-from-request.md: duplicate check, then `python3 ${live}/create_row.py --spec <spec.json>`, kind epic, a row in the エピック data source ${epic_ds}, 種別 プロダクト開発) and set this row's エピック relation to it; the next intake takes it as an epic task.
