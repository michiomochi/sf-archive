What the lines mean:
 - `controller heartbeat ...`: the gate controller (cron 'SF ゲート制御（${gate_every}）', heartbeat ${state_dir}/epic_gate_status.json) has had no successful run for 10 minutes; read its latest cron output for the ERROR/FAIL line and fix the cause.
 - `journal ...`: partial card creation (${state_dir}/epic_gate_journal.json); the controller resumes it by itself. If it persists, find the FAIL line in the controller output. A FAIL 'idempotency key ... already done' means an old finished card of the same phase blocks the new one: archive the old card (`hermes kanban --board ${board} archive <card id>`), then reset the row to 未着手 if it is not, and the controller creates the new card.
 - `<epic8> <phase>: row 進行中 but no live card (stuck)`: if the last card finished and the reviewer approved, report it (❓) with 完了 as the recommendation; otherwise archive the old card, then reset the row to 未着手 so the controller restarts the phase.
 - `<epic8> card <id> ready but not started (stalled)`: the dispatcher parks the card. If the reason is blocker_auth and the last failure text is only an old 'rate-limited (quota wall)' message, the card is parked by a stale text, not by auth: clearing it is a one-row UPDATE of tasks.last_failure_error in ~/.hermes/kanban/boards/${board}/kanban.db that this cron cannot run (no heredoc, no python -c, no sqlite3), so report it (❓) with the card id, the evidence and the exact statement `UPDATE tasks SET last_failure_error=NULL WHERE id='<id>' AND status IN ('ready','review')`, and recommend applying it. If the reason is something else, diagnose it and fix or report.
 - `order: <later phase> live while <earlier phase> not 完了`: phases ran out of order. Block the later card (`hermes kanban --board ${board} block <id>`) until the earlier phase row is 完了 and report it (❓) with the cause.
