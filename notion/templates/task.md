# 概要 {color="yellow_bg"}
この行が扱う作業の目的と完了条件を、検証できる形で書きます。表は4行だけです。カードIDは作業メモの1行目に書きます。重複確認は作る前に必ず行いますが、記録欄はありません。

# やることチェックリスト {color="yellow_bg"}
工程の成果物を順に並べます。カードの本文はこの項目から組み立てられるので、項目が空の行はゲート制御がキャンセルにします。

- [ ] 要件書の子ページを作る
- [ ] 設計書と見積もりを作る
- [ ] 実装してブランチに push する
- [ ] テストを実行し、結果を残す
- [ ] リリース判定書の草稿を作る

# 作業メモ {color="yellow_bg"}
進めた内容を1行ずつ残します。長い作業では、時刻と今やっていることを書いて生きている印にします。

# 完了レポート {color="yellow_bg"}
チェックリストが全部チェック済みで、この章に根拠があるときだけ完了にします。成果物（子ページ・ブランチ）のリンクは、該当する節に直接書きます。AI レビューへの依頼（再確認してほしい点）は、`hermes kanban request-review` のコメントに書きます。人の判断はレビュー DB の行で受けます。

## 実施内容 {color="blue_bg"}
何をしたかを、成果物ごとに書きます。成果物の子ページとブランチへのリンクはここに置きます。すべての URL はリンクにします。

## 結果 {color="blue_bg"}
どうなったかを書きます。数字は出典と時点を添えます。

## 確認した方法 {color="blue_bg"}
実行したコマンドと、実際の出力を貼ります。

## 未確認・残件 {color="blue_bg"}
確認できていないことと、残っている作業を書きます。事実、仮説、未確認を分けます。

## 次のタスク {color="blue_bg"}
続きがあるなら、次の行にすることが分かる形で書きます。
