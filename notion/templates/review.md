# 判断すること {color="yellow_bg"}
決めてほしいことを、1文で書きます。リリース承認の行では、ゲート制御が「『エピック名』の成果（リポジトリのブランチ）を、リリースしてよいと認めるか」と、承認・差し戻し・取り下げをすると何が起きるかの3行を、決まった文で書きます。承認すると、下書き PR が公開され、squash でマージされ、登録された repo は本番へ反映されます。

# 推奨 {color="yellow_bg"}
推奨を1つに決めて、理由を書きます。リリース承認の行では、ゲート制御がリリース判定書の「推奨」を写し、完了条件の達成数の行（達成・一部・未達・未実施）と、推奨が承認なのに達成でない条件があるときの注意の行を足します。判定書から読めないときは「未確認」と書かれます。

# 人が確かめること {color="yellow_bg"}
人が自分で確かめる点を、多くて5件。「何を／どこで（リンク）／目安の分数」の形で書きます。リリース承認の行では、判定書の「人が確かめること」の写しです。

# 完了条件の達成状況 {color="yellow_bg"}
完了条件ごとの状況（達成・一部・未達・未実施・対象外）と根拠の表です。リリース承認の行では、判定書の表の写しです。

# 何を出すか {color="yellow_bg"}
リポジトリ、ブランチ、先頭コミット、差分の規模、中身。UI 変更なら変更前・変更後の画像（各1枚以上。画像が判定書に無い UI 変更は、依頼が作られません）。

# 残っている危険と未確認 {color="yellow_bg"}
「残っている危険」と「未確認」の2つの見出しで書きます。リリース承認の行では、判定書の写しです。

# 根拠（開くページ） {color="yellow_bg"}
判断のもとになるページ、ブランチ、数字へのリンクを置きます（成果物のリンクはプロパティではなく、ここに書きます。非公開のものはここにだけ書きます）。リリース承認の行では、リリース判定書、PR 本文の下書き、各工程の成果物、工程の行、ブランチ、エピックへの直接リンク（12件まで）と、写した時刻・判定書の最終更新が入ります。食い違うときは判定書が正です。

# 判断の結果 {color="yellow_bg"}
この行のステータスを、承認・差し戻し・取り下げのどれかにしてください。差し戻すときは、理由をこの行のコメントか本文に書いてください。決めるのは人だけです。AI はこの章を書き換えません。

# 反映の記録 {color="yellow_bg"}
この行のキーと、反映ジョブが決定を SSOT のどこに反映したかを1行書く場所です。書いたあとに反映済みへチェックを入れます。キーは、エピック ID の末尾8桁に -承認 を付けます（例: 1e311667-承認）。差し戻しのあとは末尾に -r2、-r3 を付けます。
