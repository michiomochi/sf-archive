# 推奨 {color="yellow_bg"}
推奨：承認　（差し戻しにするときは「推奨：差し戻し」。1 行目はこの 2 つのどちらかで始める）
〈理由を 1〜3 行で。完了条件のうち達成でないものがあるなら、承認でよい理由をここに書く〉

# 人が確かめること {color="yellow_bg"}
〈人が自分の目で確かめる点を、多くて 5 件、1 件 1 行（120 字以内）で。「何を／どこで（リンク）／目安の分数」の形。無ければ「なし」と書く〉
1. 〈何を〉：〈どこで（リンク）〉（〈n〉分）

# 何を出すか {color="yellow_bg"}
- リポジトリ：〈owner/repo〉
- ブランチ：〈michiomochi/…〉、先頭コミット 〈ハッシュ〉
- 差分の規模：〈n ファイル、+行／−行〉
- 中身：〈変更の中身を箇条書きで〉
- PR：下書き（ゲート制御が、この判定書の「PR 本文」の章から作る。URL は依頼を作るときに入る）
- UI 変更：〈あり／なし〉（あり なら、変更前・変更後の画像をこの章に入れる。キャプションに「変更前」「変更後」）

# 完了条件の達成状況 {color="yellow_bg"}
状況の語は 達成・一部・未達・未実施・対象外 のどれかで始める。行はエピックの完了条件の各項目（番号つきの条件があるときは、その数と同じ行数にする）。
<table fit-page-width="true" header-row="true">
<tr><td>完了条件</td><td>状況</td><td>根拠</td></tr>
<tr><td>〈① …〉</td><td>〈達成〉</td><td>〈確かめた方法と結果。コマンドと出力、ページへのリンク〉</td></tr>
</table>

# 残っている危険 {color="yellow_bg"}
〈危険と、その大きさ・起きたときの影響を箇条書きで。無ければ「なし」と理由〉

# 未確認 {color="yellow_bg"}
〈確かめていないことと、確かめる人・時期・答えで何が変わるかを箇条書きで。無ければ「なし」〉

# 承認のあとに起きること {color="yellow_bg"}
承認すると、下書き PR が公開され、squash でマージされ、登録された repo は本番へ反映されます。追加の指示は要りません。

# 戻し方 {color="yellow_bg"}
〈本番反映の前と後それぞれで、どう元に戻すか〉

# PR 本文 {color="yellow_bg"}
〈下書き PR の本文になる章（別ページは作らない）。この行は消す。1 行目に「タイトル：…」、続けて「## 概要」「## 背景」「## 変更内容」「## 検証」の 4 節を中身ありで書く（なければ「なし」）。公開されるので、非公開の記録へのリンク・DB 名・タスクの題は書かない〉
タイトル：〈PR のタイトル〉

## 概要
〈何を変えるか〉

## 背景
〈なぜ今必要か。出典つき〉

## 変更内容
〈変更の中身〉

## 検証
〈実行したコマンドと結果。実行していない確認は書かない〉
